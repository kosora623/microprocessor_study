# 課題2 answer.md（問題2: 資料PDFより）

## 1. プログラムコード (test1.asm, 課題1と同一)

```nasm
global _start
section .text
_start:
    mov rax, 10
    mov rbx, 20
    add rax, rbx
```

同じソースコードを、NASMのデフォルト設定（最適化あり, `-Ox`）と `-O0`（最適化なし）の
2通りでアセンブルして比較する。

```
nasm -f elf64 -o test1_default.o test1.asm      # デフォルト = -Ox（多段階最適化）
nasm -O0 -f elf64 -o test1_O0.o test1.asm       # 最適化オフ
```

（NASMのマニュアルによれば `-O0` は "no optimization"、何も指定しない場合のデフォルトは
`-Ox`="multipass optimization" である。）

## 2. 説明

ソースコード上は両方とも全く同じ `mov rax, 10` / `mov rbx, 20` であるが、
NASMのアセンブル時最適化の有無によって生成される機械語のバイト数が異なる。

- **デフォルト（最適化あり）**: `mov eax, 0xa`（5バイト）
- **`-O0`（最適化なし）**: `movabs rax, 0xa`（10バイト）

## 3. 実行ログ（逆アセンブル結果）

```
$ objdump -d -Mintel test1_default.o   （デフォルト, 最適化あり）
0000000000000000 <_start>:
   0:	b8 0a 00 00 00       	mov    eax,0xa
   5:	bb 14 00 00 00       	mov    ebx,0x14
   a:	48 01 d8             	add    rax,rbx

$ objdump -d -Mintel test1_O0.o        （-O0, 最適化なし）
0000000000000000 <_start>:
   0:	48 b8 0a 00 00 00 00 	movabs rax,0xa
   7:	00 00 00
   a:	48 bb 14 00 00 00 00 	movabs rbx,0x14
  11:	00 00 00
  14:	48 01 d8             	add    rax,rbx
```

## 4. バイナリ対応表

| ビルド方法 | アドレス | 機械語Hex | 命令長 | アセンブリ表示 |
|---|---|---|---|---|
| デフォルト | 0 | `b8 0a 00 00 00` | 5バイト | `mov eax, 0xa` |
| `-O0` | 0 | `48 b8 0a 00 00 00 00 00 00 00` | 10バイト | `movabs rax, 0xa` |

## 5. 考察（元の命令 `mov rax, 10` とディスアセンブル結果が異なる理由）

### 理由①: 命令長の削減（50%削減）
ソース上は `mov rax, 10` と64bitレジスタを指定しているが、NASMのデフォルトの
多段階最適化（`-Ox`）は、即値が32bit符号なし範囲に収まり、かつ上位32bitを
ゼロにしたいだけなら、意味的に等価な短い命令形式に置き換えてよいと判断し、
`mov eax, 0xa`（オペコード`b8`+32bit即値=5バイト）にエンコードする。
一方 `-O0` を指定すると、この命令選択最適化が無効化され、ソースの指定通り
素直に64bitレジスタへの `movabs rax, 0xa`（REX.W+オペコード+64bit即値=10バイト）
がそのまま使われる。同じ値をレジスタにセットするのに、前者は後者のちょうど
半分（50%削減）のバイト数で済む。

### 理由②: x86-64 の32bitレジスタ書き込み時の上位32bitゼロ拡張仕様
この最適化が安全に行える根拠は、x86-64のアーキテクチャ仕様にある。
32bit汎用レジスタ（`eax`, `ebx`, ... など）へ書き込みを行うと、
対応する64bitレジスタ（`rax`, `rbx`, ...）の **上位32bitは自動的に0でクリアされる**
という仕様があるためである（16bit/8bitレジスタ操作には適用されない、
32bit操作専用の特別ルール）。

したがって `mov eax, 0xa` を実行すると:
- 下位32bit (`eax`) に `0xa` が書き込まれる
- 上位32bitは自動的にゼロ拡張される

結果として `rax` 全体は `0x000000000000000a` となり、`movabs rax, 0xa` と
全く同じ実行結果が得られる。この等価性が保証されているからこそ、
NASMのデフォルト最適化は安全に5バイト版へ置き換えることができ、
`-O0` ではこの最適化が無効化されるため素直な10バイトのエンコーディングになる。
