# 課題5(5)(6) binary.md

`riscv64-linux-gnu-as`（RV32Iターゲット）でアセンブルし `riscv64-linux-gnu-objdump` で実際に確認した。

## (5) `t1` に `0xCA` を格納: `addi t1, x0, 0xca`

### I-type フォーマット

```
| imm[11:0]      | rs1   | funct3 | rd    | opcode  |
|  12bit         | 5bit  | 3bit   | 5bit  | 7bit    |
```

| フィールド | 値 | 2進数 |
|---|---|---|
| imm[11:0] | `0xCA` = 202 | `0000 1100 1010` |
| rs1 | `x0` | `00000` |
| funct3 | `000`（ADDI） | `000` |
| rd | `t1` = `x6` | `00110` |
| opcode | `ADDI`系(OP-IMM) | `0010011` |

ビット連結（MSB→LSB）:
```
000011001010 00000 000 00110 0010011
```
= `0000 1100 1010 0000 0000 0011 0001 0011`
= **`0x0CA00313`**

リトルエンディアンのバイト列: **`13 03 a0 0c`**

### 実アセンブルによる確認
```
$ riscv64-linux-gnu-objdump -d rvbin1.o
0:	0ca00313          	li	t1,202
```
`0ca00313` となり、期待値 `0x0CA00313` と完全に一致した。

## (6) `t1` に `0xCAFEBABE` を格納: `lui t1, 0xCAFEC` + `addi t1, t1, 0xABE`

`0xCAFEBABE` は32bit幅のためI-type即値(12bit)1つでは表現できず、
`lui`（上位20bit）+ `addi`（下位12bit）の2命令で合成する。

### 符号拡張補正の計算プロセス

1. `0xCAFEBABE` を上位20bitと下位12bitに分割する:
   - 下位12bit: `0xBABE & 0xFFF = 0xABE`
   - 上位20bit（本来の値）: `0xCAFEBABE >> 12 = 0xCAFEB`
2. `addi` の即値は**符号付き12bit**として扱われる。`0xABE`は2進数で`1010 1011 1110`であり
   最上位ビット(bit11)が`1`であるため、符号付きとして解釈すると負の値
   `0xABE - 0x1000 = -1346` になる。
3. もし上位20bitをそのまま `0xCAFEB` として `lui` した後に `addi t1,t1,0xABE`（実際には -1346）を
   加算すると、`0xCAFEB000 - 1346 = 0xCAFEAABE` となってしまい、目的の `0xCAFEBABE` より
   `0x1000` 小さい値になってしまう。
4. この「`addi`が負の値として1個分（`0x1000`）引いてしまう」ことを相殺するため、
   アセンブラは **上位20bitに あらかじめ+1 した `0xCAFEC`** を `lui` にロードする。
   - `lui t1, 0xCAFEC` → `t1 = 0xCAFEC000`
   - `addi t1, t1, -1346`（`0xABE`の符号付き解釈） → `t1 = 0xCAFEC000 - 1346 = 0xCAFEBABE`
5. 結果として正しく `t1 = 0xCAFEBABE` が得られる。

### U-type フォーマット (`lui t1, 0xCAFEC`)

```
| imm[31:12]        | rd    | opcode  |
|  20bit             | 5bit  | 7bit    |
```

| フィールド | 値 | 2進数 |
|---|---|---|
| imm[31:12] | `0xCAFEC` | `1100 1010 1111 1110 1100` |
| rd | `t1` = `x6` | `00110` |
| opcode | `LUI` | `0110111` |

ビット連結: `11001010111111101100 00110 0110111` = **`0xCAFEC337`**

### I-type フォーマット (`addi t1, t1, 0xABE` ※符号付き-1346)

| フィールド | 値 | 2進数 |
|---|---|---|
| imm[11:0] | `0xABE`（符号付き-1346） | `1010 1011 1110` |
| rs1 | `t1` = `x6` | `00110` |
| funct3 | `000` | `000` |
| rd | `t1` = `x6` | `00110` |
| opcode | OP-IMM | `0010011` |

ビット連結: `101010111110 00110 000 00110 0010011` = **`0xABE30313`**

### 実アセンブルによる確認
```
$ riscv64-linux-gnu-objdump -d rvbin2.o
0:	cafec337          	lui	t1,0xcafec
4:	abe30313          	addi	t1,t1,-1346
```
`cafec337` / `abe30313` となり、いずれも期待値 `0xCAFEC337` / `0xABE30313` と完全に一致した。
