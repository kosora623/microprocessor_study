# 課題4 answer.md

## 1. 検証用コード

```asm
.text
.globl _start
_start:
    li t0, 10          ; (a) 12bit範囲に収まる即値
```
```asm
.text
.globl _start
_start:
    li t0, 0xCAFEBABE  ; (b) 32bit範囲の即値
```

アセンブル・逆アセンブル:
```
riscv64-linux-gnu-as -o li1.o li1.s
riscv64-linux-gnu-objdump -d li1.o
riscv64-linux-gnu-as -march=rv32i -mabi=ilp32 -o li2_32.o li2.s
riscv64-linux-gnu-objdump -d li2_32.o
```

## 2. 説明

### (a) 12bit範囲（-2048〜2047）に収まる場合

`li t0, 10` は `addi t0, x0, 10` 1命令に展開される。

```
0:	00a00293          	li	t0,10
```
（`00a00293` は I-type の `addi` エンコーディングそのものであり、objdumpも
`addi rd, x0, imm` を `li` の表示に戻して見せている。）

RISC-V の I-type 即値フィールドは12bit符号付きであるため、この範囲に収まる即値であれば
ゼロレジスタ `x0` に対して1回 `addi` するだけで任意の値をレジスタにロードできる。

### (b) 32bit範囲の場合

`li t0, 0xCAFEBABE` は32bit幅の値であり12bitには収まらないため、
`lui`（上位20bitをロード）+ `addi`（下位12bitを加算）の2命令に展開される
（RV32ターゲットでアセンブルした場合）。

```
0:	cafec2b7          	lui	t0,0xcafec
4:	abe28293          	addi	t0,t0,-1346
```

ここで下位12bit `0xABE` はビット11が1（符号付き12bitとして負の値 `-1346`）であるため、
`addi` は符号拡張されて `t0` の値を1小さい方向に動かしてしまう。これを補正するために、
アセンブラは `lui` に渡す上位20bitの値を本来の `0xCAFEB` ではなく **+1 した `0xCAFEC`** にしている。

```
lui  t0, 0xCAFEC       ; t0 = 0xCAFEC000
addi t0, t0, 0xABE(-1346) ; t0 = 0xCAFEC000 - 1346 = 0xCAFEBABE
```

このように「下位12bitの符号拡張による減算分をあらかじめ上位20bitに+1して相殺する」のが
`li` 擬似命令の lui+addi 展開における補正ロジックである。

（補足: 64bit (`RV64`) ターゲットでフルの64bitレジスタとして厳密にゼロ拡張したい場合、
アセンブラは `lui`+`addiw`+`slli`+`addi` のようなより長い命令列を生成することがある。
これは `lui`/`addi` の結果が64bit環境では符号拡張されるため、上位32bitまで正確に
制御する必要が生じるためである。ただし「12bitならaddi 1命令、32bit値ならlui+addiの2命令」
という基本メカニズム自体はRV32・RV64共通であり、本課題で問われている本質的な仕組みである。）

## 3. RISC-Vの設計思想

RISC-V には x86 の `mov` のような「レジスタに即値を代入する専用命令」が存在しない。
その代わりに、

- **`x0`（ゼロレジスタ）**: 読み出すと常に0、書き込みは無視されるハードワイヤードレジスタ
- **ALU（加算器）**: `addi rd, rs1, imm` という「`rs1` に即値を加算して`rd`に書く」命令

という既存の2つの部品を組み合わせることで、「`addi rd, x0, imm`」＝「0 + imm を rd に書く」
という形で代入命令を**合成**している。

これは RISC（Reduced Instruction Set Computer）の設計思想を体現したものである。

- 専用の「ロード即値」命令を追加するとデコーダやエンコーディング空間（オペコード）を
  新たに消費するが、`addi`+`x0`の組み合わせで同じ機能を実現できるなら、
  命令セットを増やす必要がない。
- ハードウェア側は「汎用加算器＋ゼロレジスタ」という単純な部品の再利用だけで済み、
  特別な代入専用のデータパスを追加する必要がない。
- 32bitを超える即値（`lui`+`addi`）についても、同じ加算器を使って
  「上位20bitをロードした値」に「下位12bitを加算する」という形で合成しており、
  一貫して「代入＝0または既存の値への加算」という単純なモデルに統一されている。

このように、RISC-Vは専用命令を増やすのではなく、`x0` と加算器という最小限の既存ハードウェアを
使い回すことで命令セットとデコーダの複雑さを抑える、という一貫したRISC哲学に基づいている。
`li` はあくまでアセンブラが提供する擬似命令であり、実際の機械語には存在しない点も重要である。
